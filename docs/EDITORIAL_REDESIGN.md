# Mixture of Insights：编辑与页面改造方案

日期：2026-09-14。目标仓库：`wangtong10086/mixtureofinsights`。

本文保留最初的实现任务书与验收范围；实际实现、测试结果及未测项见 [REDESIGN_VALIDATION.md](REDESIGN_VALIDATION.md)，内容疑问见 [EDITORIAL_AUDIT.md](EDITORIAL_AUDIT.md)。工作分支：`codex/editorial-redesign-20260914`；目标分支：`master`。未经作者另行授权，不合并、不部署。

## 1. 决策：技术笔记的编辑版，而不是换一种 AI 模板

定位不变：王通的中英双语技术博客，围绕后训练、Agent、推理与系统工程。改造的目的，是让读者更容易发现文章、沿项目阅读、检查论据，而不是让页面显得更昂贵，或把作者包装成另一种人设。

采用 **editorial engineering notebook** 方向：有明确编辑取舍的技术笔记。保留现有暖色背景、衬线标题和低干扰阅读；以文章标题、日期、项目关系、可验证的细节形成辨识度。首页用较宽的索引布局，正文维持较窄的阅读栏。少装饰，不能少证据。

不采用另外两种方向：黑底终端/ASCII 装饰的“黑客主页”会把写作人设问题换成视觉人设；大封面、巨型标语和卡片矩阵的“独立杂志”会继续让宣传性内容压过工程内容。不要再输出三套候选让任务停在选风格；按上述方向实现，截图后校正。

## 2. 已核对的代码依据

以下是源码观察，不等同于已经完成全部浏览器测试：

| 文件 | 当前行为 | 改造理由 |
| --- | --- | --- |
| `src/components/Home.astro` | 固定三篇 featured；随后遍历所有系列，再次完整展示文章；列表逐篇渲染 `/og/<slug>.jpg` | 首页精选与系列重复；装饰图和摘要扩大滚动成本；最近更新不容易被发现 |
| `src/components/Post.astro` | 每篇无条件显示大封面；标题后依次为摘要、标签、封面和默认展开的目录 | 正文前内容较多；不是所有技术文章都需要装饰性头图 |
| `src/styles/global.css` | 首页和正文主要共用 `--measure: 44rem`；featured 三等分；`.hero` 的 padding 会覆盖 `.wrap` 横向 padding | 索引和长文是不同任务；移动端首屏边距需真实检查，不能只看构建结果 |
| `src/i18n.ts` | 首页简介和系列说明包含较多修辞；同时负责语言、slug 和系列注册 | 应简化文案，但保留现有标识、排序与双语映射 |
| `src/layouts/Base.astro` | 已有 canonical、hreflang、OG、JSON-LD、主题开关和分析脚本；RSS alternate 固定 `/rss.xml` | SEO 不是重做对象；需要保护并补上中文 RSS 等局部问题 |
| `src/components/Comments.astro` | giscus 使用 pathname 映射，并监听 `themeToggle` | 改 URL 或随意替换开关会破坏既有评论关联或主题联动 |
| `.agents/skills/hardcore_tech_blog/SKILL.md`（改造前） | 强制第一人称、固定瓶颈叙事、ASCII 偏好、禁止总结、要求“信息量拉满” | 这些固定约束可能使不同文章趋同；应换成证据与读者任务优先的编辑规则 |
| `.github/workflows/deploy.yml` | `master` push 自动构建并部署 Cloudflare | 所有工作留在任务分支；不能为预览而推送 master |

`README.md` 已明确把该站定位成真实项目驱动的技术博客，而不是简历。沿用这个定位，不添加未经核实的履历、客户、业绩或“正在进行”状态。

## 3. 首页与信息架构

### 3.1 首页

页面顺序：简短站点说明 → 最近文章 → 紧凑系列索引 → 全部文章入口。桌面可以把系列索引放在右侧窄栏；移动端恢复同一逻辑顺序，不以 CSS 重排打乱阅读或键盘顺序。

首屏只显示一次显著站名，不同时出现同样醒目的导航品牌与巨型重复标题。作者说明是一两句具体事实，不是使命宣言。参考文案（可依据已公开内容微调）：

- EN: `Technical notes by Wang Tong on post-training, agents, inference, and systems debugging.`
- ZH: `王通的技术笔记，记录后训练、Agent、推理部署和系统排查。`

最近文章默认最多 6 篇，来自当前语言的所有文章，按原始 `date` 降序、slug 作稳定次级排序。明确使用一致的日期时区，避免构建环境导致日期前后偏移。不要修改 front-matter 日期来制造更新感。展示日期、标题、可选的一句摘要和系列链接；不使用装饰缩略图、卡片外壳、编号前缀或标签云。

精选可以保留为最多两条紧凑文字链接，但不得重复最近文章的整块标题、摘要与图片；若没有独立编辑价值，就不显示精选区。不要通过虚构“编辑精选理由”填补空白。

系列索引列出名称、实际文章数量和可选的事实性说明。数量由 collection 计算；不要手写 active、持续更新、近期在做等未经确认的状态。系列本身有价值，取消的是首页将所有系列正文目录全部展开的方式。

### 3.2 新增页面

新增 `/archive/`、`/zh/archive/`：完整文章列表，按原始日期分年。以紧凑文本行为主，不复制首页的长摘要和封面。页面无需搜索框、筛选系统或客户端应用壳。

新增 `/series/<key>/`、`/zh/series/<key>/`：仅为当前语言实际存在的系列生成页面。系列内部继续按原来的 `order` 排列，显示当前语言的名称与说明。只在这里保留章节顺序信息；前后篇导航仍使用原来的系列语义。

用共享组件渲染双语 archive/series，避免两份逻辑漂移。已有 `/blog/<slug>/` 与 `/zh/blog/<slug>/` 完全不变，链接末尾斜杠保持现有可访问性。语言切换、canonical、hreflang、sitemap 要覆盖新增页面；只为真实存在的对应语言页面输出 alternate。

建议导航：Writing/文章（首页）、Archive/归档、About/关于、语言、主题。Series 从首页和文章系列链接进入即可，不必每种维度都加顶栏入口。RSS 在适当位置提供当前语言入口。

## 4. 视觉和文章阅读

### 4.1 尺度与组件

优先复用现有字体和配色，不把改色当作设计工作。允许精调，但解释目的。建议起点：索引总宽约 1040–1120px，主列加 200–240px 系列栏；正文约 42–46rem；手机左右留 20–24px。这些是设计起点，不是强制像素验收值，以真实内容截图决定最终值。

英语标题沿用 Newsreader 或现有回退；中文使用合理的本地中文字体回退，不能假设英语字体包含中文字形。中文标题不要照搬英文的紧行高与负字距。中英正文分别检查行长、长标题和混排代码，字号通常从 17–18px 起，正文行高约 1.65–1.85。

标题、日期、正文、辅助信息应有清楚层级；不能用极浅文字制造“高级感”。链接可识别且有键盘焦点。用间距、细分隔线、排版区分内容，不默认给每段添加圆角背景。

不要引入渐变光晕、玻璃效果、伪终端、随机错位、假手写、装饰性网格、滚动入场动画或新的三卡片矩阵。自然并不等于故意不规整。

### 4.2 图片

首页/归档/系列列表移除现有装饰性 AI 封面。文章默认不展示装饰性封面。保留 `public/og/` 文件与现有 OG 分享元数据，避免删除资产或改变分享行为。确有说明价值的正文图、诊断图、实验图、截图和 SVG 不删除。

必要时新增可选的 `showCover` 字段，默认关闭，避免逐篇添加 `false`；只有确有理由的文章才显式开启。不要调用图片生成服务或重跑 `scripts/gen-covers.py`。本轮目标是减少无信息图像，不是生成一批更像真人做的装饰图。

### 4.3 正文页

标题后保留实际日期、系列链接和可选摘要；摘要若只重复第一段，可以不在正文头部重复显示，但 metadata 描述仍要保留。标签降低权重，不让胶囊标签抢过内容。

宽屏可用正文侧边的目录；窄屏用可展开目录，长目录默认折叠以减少首屏占用。原生 HTML 优先。保留 heading ID 和锚点，处理长标题及定位偏移。

代码、公式、表格只在各自容器内横向滚动，不使整个页面溢出。不要改代码、公式或图表数值。无 JS 时文章、目录链接和导航仍然可读可用。阅读进度条若保留，应按正文阅读范围计算，不把评论长度算进进度；不要为微小装饰引入新的运行时库。

主题切换需保持选择、适配系统主题并与 giscus 联动。图标按钮有本地化名称、可见焦点和足够触摸区域；尊重 reduced-motion。补上 skip link 和主内容定位。检查移动端导航换行、200% 缩放、深色公式和内嵌图表。

## 5. 文字编辑：先证明，再删修辞

### 5.1 分层处理

本轮修改首页简介、系列说明、界面文案，以及 About 页的冗余介绍。About 保留可核实的工作方向、项目和联系方式；具体 benchmark/履历数字若来源不足，记录为待核对，不悄悄改写成另一项成绩。

抽样编辑 `post-training-is-a-data-problem` 与 `when-the-gpu-isnt-an-nvidia` 的中英文版本：读完整篇后，对 description、开头和明显冗余段落做局部改写。若文件发生变化或某个语言版本不存在，先按实际文件树确认，不猜路径。其余文章本轮只做审计，不批量重写。

建立 `docs/EDITORIAL_AUDIT.md`：文件/段落、原句、问题类别、证据位置、建议、是否可自动修改。检查全站摘要与高风险绝对化语句，但不声称完成未读文章的逐句审核。

### 5.2 三类改动，不能混在一起

1. **纯编辑**：删除重复背景、抽象口号和无信息转折；不改变结论范围。可直接修改。
2. **需核验的技术内容**：绝对化论断、无条件保证、公式假设、性能比较。检查 `docs/SOURCES.md` 及其引用；证据不足只标注审计，不擅自得出相反结论。
3. **作者经历与测量**：耗时、预算百分比、失败经历、内部实验结果、个人动机。源码不能证明这些。不得为“自然”虚构补充，也不能在没有证据时把它们改成更可信的新故事。

已读的 `src/content/blog/en/post-training-is-a-data-problem.md` 包含 `the loss function is mostly irrelevant`、`I dedicate zero engineering time`、`90% of my compute and engineering budget` 等句子。本方案并不判定它们为假；它们是需要作者记录或范围限定才能评估的候选，不能仅靠去 AI 味编辑处理。公式中的独立性假设与示例参数也应在技术审计中单独检查。

可参考的 description 改写（基于文中已有主题，不冒充新实验结果）：

- EN: `How ORBIT generates, filters, and verifies training trajectories, and how acceptance rate affects the cost of collecting data.`
- ZH: `ORBIT 如何生成、筛选和验证训练轨迹，以及通过率如何影响数据收集成本。`

这比把旧的强断言替换成“我后来发现真正重要的是……”更安全；后者仍在创造个人发现叙事。技术观点可以有锋芒，但不能每段都靠金句推进。

不机械禁用破折号、总结、三点列表、第一人称或某个技术形容词。也不要求随机短句、错别字、网络用语和刻意不对称。验收看信息、证据与节奏，不看 AI detector 分数。

### 5.3 持久规则

更新现有 `hardcore-tech-blog` Skill，保留调用名但取消强制人设、固定结构和图表格式。增加站点专用 `editorial-site-redesign` Skill，负责审计 → 小范围实现 → 渲染检查 → 回归。不要同时叠加多个相互矛盾的第三方 humanizer/design Skill。

## 7. 验收与测试

### 可执行检查

使用现有 Node 22 与 lockfile，首先 `npm ci`、`npm run build`。开始前保存基线构建的文章路径和内容标识；完成后比较所有旧文章仍存在，没有改日期、slug、series/order、代码块、公式和源码链接。新增路径不应让旧路径消失。

根据实际仓库添加轻量脚本，检查内部链接、两种语言页面、RSS、sitemap、canonical/hreflang 与 giscus 映射。不要把 `npm run build` 当作类型检查；需要类型检查时显式添加并运行相应命令。可添加 Playwright 测试依赖，但不能宣称没有运行的浏览器测试已通过。

PR 检查工作流只允许 checkout、安装、构建、测试和上传测试产物；使用最小只读权限，不带 Cloudflare secrets，不触发部署，不使用 `pull_request_target` 执行分支代码。

### 浏览器矩阵

至少检查 390、768、1440px 宽度；英文/中文；浅色/深色；首页、归档、系列页与两篇代表正文。额外检查 320px 导航和长内容溢出。矩阵可以自动截图，至少人工/视觉审阅各类页面的代表截图，记录哪些组合未看。

重点检查：标题换行、首屏信息层级、列表与段落密度、无整页横向滚动、公式/代码/表格局部滚动、目录定位、前后篇、语言切换、主题持久化、giscus 主题联动、键盘导航、200% 缩放、reduced-motion 和禁用 JS 的主要阅读流程。

外部 giscus 或字体加载失败时，区分第三方网络限制与本地代码失败；不要为了“测试通过”移除功能。若浏览器不可用，保留任务与未测清单，不编造截图、分数或通过结论。

### 完成标准

- 首页不再完整重复展示精选文章与各系列全部文章。
- 首页/归档/系列列表没有无信息装饰封面；正文默认无装饰性大头图，OG 资产仍在。
- 最近文章、完整归档和系列顺序三种发现方式均可用；旧链接和双语功能不受损。
- 网站文案更具体，未新增事实或人设；样本文章内容边界和未决问题可审查。
- 有实际成功的构建记录与诚实的浏览器验证记录，没有新增明显可访问性/溢出回归。
- 所有实现留在草稿 PR；未合并、未部署、未启用自动合并。
